# 需求分析：万能视频下载网站

## 1. 背景与问题

许多用户希望将视频 **保存到本地**，但常遇到：

- 平台 **不提供下载**，或下载入口隐蔽；
- **不方便**：不支持批量、清晰度受限、移动端体验差；
- **多平台**：链接来源分散（YouTube、Bilibili、抖音、TikTok 等），缺少统一入口。

本项目目标是做一个 **万能视频下载网站**：更快、随时可用、多平台支持，**手机浏览器也能用**。

## 2. 产品定位与原则

| 维度 | 说明 |
|------|------|
| 定位 | 学习向工程实践：前后端分离 + 站在开源巨人肩膀（yt-dlp）上封装能力 |
| 合规 | **尊重版权**；页面需提示学习研究用途；不引导绕过平台付费/会员内容 |
| 风险 | 部分平台可能限制抓取或存在封号风险，需在文案与错误提示中如实说明 |
| 变现 | 可预留「付费能力、视频总结、字幕翻译」等方向，**MVP 不实现** |

## 3. 用户与场景

**主要用户**：有本地存档需求的普通用户（含移动端）。

**核心场景（MVP）**

1. 打开网站 → 粘贴视频链接 → 解析出标题、封面、可选清晰度；
2. 选择清晰度 → 一键下载到本地（浏览器保存对话框）；
3. **下载方式由后端自动选择**（服务端落盘 / 直链 / 代理）；MVP **不在界面暴露** server/direct 等术语（API 仍保留 `prefer_mode` 供调试与后续扩展）。

**非 MVP 场景（后续）**

- 账号体系、订阅付费、次数限制；
- 播放列表/批量下载；
- 字幕文件单独下载、字幕翻译；
- 生产环境部署、CDN、对象存储。

**Phase 3 第一期（已交付：字幕轨学习笔记，无登录）**

- 解析成功后四个按钮分块生成：带时间戳大纲、核心要点、思维导图、字幕原文（不做总览）；
- 生成过的块以 Tab 切换，可回看；导出复制、`.md`；大纲/要点/字幕可另存 Word 兼容 `.doc`；
- 文本来源：平台官方/自动字幕轨；烧录字、弹幕、多数抖音明确失败，不做 ASR；
- 脑图：页面为只读画布（中心放射），可全屏查看、导出 PNG；Markdown 导出仍带嵌套列表备份；时间戳只展示，不跳播；
- 大模型：DeepSeek `deepseek-flash`（JSON Mode，关掉 thinking）；字幕块不调模型；
- 不做：登录、配额会员、画面理解、改写发布、内嵌播放器。

**Phase 3 问答（已交付：字幕轨轻量对话，详见 [08](./08-AI视频问答功能总结.md)）**

- 解析成功后，右栏 Tab「问AI」可提问；不必先生成大纲 / 要点 / 脑图 / 字幕；
- 多轮气泡，历史只留在当前页面，换链接或刷新即清空；不按视频生成建议问题（空状态可用固定示例问法填入输入框）；答案不强制带时间戳；
- 上下文与笔记同一套字幕轨。没有字幕就在问答卡片失败，不做语音转写，下载不受影响；
- 大模型仍是 DeepSeek，问答走纯文本（关掉 thinking，不用 JSON Mode）。

## 4. 功能需求

### 4.1 必须（MVP）

- **链接解析**：输入 URL，返回视频元信息与可用格式列表；
- **下载**：用户选定 `format_id` 后获取文件；
- **双模式获取文件**（见 4.2）；
- **多平台**：依赖 yt-dlp 支持范围，页面上展示主流平台说明；
- **响应式 UI**：移动端可用；
- **错误处理**：无效链接、平台不支持、缺少 ffmpeg、下载失败等可读提示。

### 4.2 下载模式（已确认）

用户获取文件的两种方式 **都要支持**，并由系统 **按平台/格式自动选最佳**（MVP 界面固定「自动」；手动偏好仅 API/后续迭代）：

| 模式 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **服务端落盘** | 服务器用 yt-dlp 下载后再提供下载链接 | 体验稳、适合分片/合并 | 占磁盘与带宽 |
| **直链** | 解析出媒体 URL，浏览器 **重定向** 或经服务端 **代理流** | 不占长期磁盘 | 部分平台直链不可用或易失效 |

自动策略失败时，应 **回退到服务端落盘**，并在 UI 说明原因。

### 4.3 明确不做（MVP）

- 注册 / 登录；
- 付费、订单、会员；
- 数据库（任务状态可用内存 + 临时目录，本地开发足够）。

## 5. 非功能需求

| 类型 | 要求 |
|------|------|
| 技术栈 | 后端 **Python**（yt-dlp 生态）；前端 **Vue 3 + Vite + Tailwind**，前后端分离 |
| 部署 | **本地开发**为主；README 写清依赖与启动方式 |
| 轻量 | 无 DB；临时文件 TTL 清理 |
| 可扩展 | 文档化 API 与策略扩展点，便于加字幕、批量、AI 等 |
| UI | 调性参考 [鱼皮 AI 绘图导航](https://ai.codefather.cn/painting)（居中搜索、卡片、工具感）；**当前实现**为蓝系 accent、未解析时居中 Hero + 三能力卡、解析后双栏（左下载 / 右笔记与问AI Tab），见 [03-设计文档.md](./03-设计文档.md) |

## 6. 人工方案输入（原始决策记录）

以下为项目发起时的关键结论，已与产品方对齐：

1. **界面**：尽量吸引人、突出实用价值（非纯炫技）；
2. **后端**：需要，但先 **不要数据库**，尽量轻量；
3. **下载实现**：多数平台使用 **yt-dlp** 薄封装；**抖音**因网页风控改用 Playwright 抽直链，不把该路径套到 B 站/油管。
4. **前端**：Vue3 + Vite + Tailwind（前后端分离、上手简单）；
5. **下载模式**：服务端落盘 + 直链（重定向/代理），自动择优；
6. **账号与付费**：当前不需要；
8. **学习笔记（2026-09-26 交付；脑图展示 2026-09-27 改为画布）**：只读字幕轨，无轨明确失败、不做 ASR；四个按钮分块生成（大纲 / 要点 / 脑图要 DeepSeek，字幕不要 Key）；生成后出 Tab 回看；脑图为只读画布（全屏、导出 PNG），不是缩进列表；复制 / `.md` 仍含该块文本；Word 兼容 doc 仅大纲/要点/字幕 Tab；时间戳只展示。详见 [06-AI学习笔记功能总结.md](./06-AI学习笔记功能总结.md)。
9. **视频问答（2026-09-26）**：解析成功即可问；只依据同一套字幕轨；无轨失败即可，不做 ASR；多轮气泡不落库、无按视频生成的建议问题、无时间戳跳播。详见 [08-AI视频问答功能总结.md](./08-AI视频问答功能总结.md)。

## 7. MVP 与路线图

```text
MVP（已实现）
  └─ 单链解析 + 清晰度选择 + 后端双模式自动下载 + 产品化 UI（无登录、无高级下载选项）

Phase 3 第一期（已实现）
  └─ AI 学习笔记：四按钮分块（大纲/要点/脑图/字幕）+ Tab 回看 + 脑图画布/全屏/PNG + 文本导出

Phase 3 问答（已实现）
  └─ 解析后轻量对话：字幕轨上下文 + 多轮气泡；无轨失败，不做 ASR

Phase 2（文档预留，未排期）
  └─ 字幕文件下载 / 仅音频 / 播放列表批量

Phase 3 后续
  └─ 字幕翻译、无字幕 ASR、建议问题 / 时间戳跳播（需播放器与配额设计）

Phase 4
  └─ 用户体系、付费能力（需合规与存储方案）
```

## 8. 验收标准（MVP）

- 本地可同时启动前端与后端，完成 **YouTube、B 站、抖音** 的解析与下载验证（抖音须已 `playwright install chromium`）；
- 移动端宽度下布局可用；用户路径为 **粘贴 → 选清晰度 → 开始下载**，错误有可读提示；
- 文档目录完整（含 [04](./04-实现与产品差异.md)、[05](./05-视频下载功能总结.md)、[06](./06-AI学习笔记功能总结.md)、[08](./08-AI视频问答功能总结.md)），AI 可仅凭 `docs/` 理解扩展边界。
- 学习笔记：带 CC 的油管可分块生成；无轨视频可读失败；下载区不被笔记打断。
- 视频问答：有字幕轨时可连续追问；无字幕轨只在问答卡片失败；下载仍可用。
