# 实现与产品差异说明

供产品与 AI 对齐：**用户看到什么** vs **后端实际做什么**。

## 1. 双下载模式：用户无感，后端有策略

| 用户界面 | 后端 |
|----------|------|
| 只有「选清晰度 → 开始下载」 | 仍按 `choose_mode` 在 `server` / `redirect` / `proxy` 间选择 |
| 固定传 `prefer_mode: auto` | API 仍支持 `server` / `direct`（调试、Postman、后续「遇到问题换方式」） |
| 不展示 `recommended_mode`、不展示 `mode` | `/api/video/info` 仍返回 `recommended_mode`、`recommended_reason` |

**原因**：「强制服务端 / 优先直链」对普通用户难理解；YouTube 等场景两种选项体验相同，易困惑。详见讨论结论：用产品语言（更稳/更快）若再上线，见 [03-设计文档.md](./03-设计文档.md) 扩展说明。

## 2. 本地开发时 server 模式与「两份文件」

当最终 `mode` 为 **server** 且前后端都在本机运行时：

1. yt-dlp（或抖音 httpx）先把文件写入 `backend/downloads/{task_id}/`
2. 浏览器再通过 `/api/video/file/{task_id}` 保存到用户选择的目录

**同一块硬盘上可能短暂存在两份**（临时目录约 1 小时 TTL 后会清理）。部署到远程服务器后，用户本机通常只有自己选择的那一份。

## 3. 清晰度文案：`stream_kind`

API 的 `formats[].stream_kind` 映射到界面（`VideoResult.vue`）：

| stream_kind | 用户可见说明 |
|-------------|----------------|
| `muxed` | 含声音 |
| `merge` | 视频+音频合并（服务端需 ffmpeg） |
| `audio` | 仅音频 |

## 4. 平台分流（用户无感）

| 用户操作 | 后端 |
|----------|------|
| 粘贴 YouTube / B 站 | yt-dlp 解析与下载；不带抖音 Cookie |
| 粘贴抖音口令或 `/video/id` | Playwright 解析，httpx 下载 |
| 粘贴抖音推荐首页 | 无法解析（没有作品 id） |

下载请求会带上所选清晰度的 `stream_kind`，便于 B 站/油管跳过第二次元数据请求。

## 5. AI 学习笔记

解析成功后出现「生成学习笔记」。用户**不必先下载**。

| 用户界面 | 后端 |
|----------|------|
| 一键生成 | yt-dlp 拉字幕 → LLM 结构化 JSON |
| Tab：大纲 / 要点 / 脑图 / 字幕 | 同一次响应里的字段 |
| 复制 / 导出 md、doc | 浏览器侧用返回的 `markdown` 生成文件 |
| 无登录、无次数展示 | 无数据库；费用在调用方的大模型账号 |

失败时只影响笔记卡片，已解析的下载区保留。
