# 项目文档索引

本目录沉淀 **需求、方案、设计**，供后续扩展功能（字幕、批量、AI 总结、付费等）时给 AI 或协作者快速对齐上下文。

## 阅读顺序

| 文档 | 用途 |
|------|------|
| [01-需求分析.md](./01-需求分析.md) | 背景、用户价值、范围边界、已确认决策 |
| [02-技术方案.md](./02-技术方案.md) | 架构、技术栈、双下载模式、yt-dlp 集成原则、风险 |
| [03-设计文档.md](./03-设计文档.md) | UI 规范、API 契约、目录结构、策略与扩展点 |

## 给 AI 的使用说明

1. **改功能前**：先读 `01-需求分析.md` 中的「MVP 范围」与「后续迭代」，避免把未排期的能力写进第一版。
2. **改下载逻辑**：以 `02-技术方案.md` 的双模式与 `03-设计文档.md` 的 `DownloadStrategy` 扩展点为准；优先 **薄封装 yt-dlp**，不 fork 改源码。
3. **改界面**：遵循 `03-设计文档.md` 的 UI 参考站与 Tailwind 约定，保持「实用价值 + 学习项目」调性。
4. **新增 API**：在 `03-设计文档.md` 的 API 章节补充契约，并同步 `02` 中架构图若涉及新模块。

## 文档变更

重大需求或架构变更时，请更新对应 md，并在文末「修订记录」增加一行（日期 + 摘要）。
