# 项目文档索引

本目录沉淀 **需求、方案、设计**，供后续扩展功能（字幕、批量、AI 总结、付费等）时给 AI 或协作者快速对齐上下文。

## 阅读顺序

| 文档 | 用途 |
|------|------|
| [01-需求分析.md](./01-需求分析.md) | 背景、用户价值、范围边界、已确认决策 |
| [02-技术方案.md](./02-技术方案.md) | 架构、技术栈、双下载模式、yt-dlp 集成原则、风险 |
| [03-设计文档.md](./03-设计文档.md) | UI 规范、API 契约、目录结构、组件清单 |
| [04-实现与产品差异.md](./04-实现与产品差异.md) | **用户可见 vs 后端行为**（隐藏下载模式、本地双份文件、stream_kind） |

可选设计稿：[design.pen](./design.pen)（Pencil；与代码不一致时以 `frontend/` 为准）。

## 给 AI 的使用说明

1. **改功能前**：先读 `01` 的 MVP 范围与 `04` 的产品差异，避免把未排期的能力或已隐藏的 UI 写回来。
2. **改下载逻辑**：以 `02` 的双模式与 `backend/services/download_strategy.py` 为准；优先 **薄封装 yt-dlp**。
3. **改界面**：以 `03` 的组件表与 `frontend/tailwind.config.js` token 为准（非初版 FeatureCards / 高级下载选项）。
4. **新增 API**：更新 `03` API 章节，必要时同步 `02` 架构说明。

## 文档变更

重大需求或架构变更时，请更新对应 md，并在文末「修订记录」增加一行（日期 + 摘要）。
